Domain 01 Agentic Architecture & Orchestration 5 patterns · 27% weight
  1. 01Critical
    Parsing natural language for loop termination.
    The model phrases completion differently every call. Searching for “anything else?” or other surface text is regex-against-probability — and text can ride alongside a tool_use block, so the agent stops mid-task.
    Inspect stop_reason directly. "end_turn" means done; "tool_use" means continue.
  2. 02Critical
    Arbitrary iteration caps as the primary stopping mechanism.
    An iteration cap is a runaway-loop guardrail, not control flow. If your loop terminates because it hit max_iterations, that’s a bug; the agent had work left to do.
    Let stop_reason == "end_turn" drive normal termination. Keep the cap purely as a safety net.
  3. 03Critical
    Prompt-based enforcement for critical business rules.
    When a question describes financial, security, or compliance failures with a non-zero failure rate, prompt-improvement options are distractors. Few-shot and clearer wording reduce failure rates but never to zero.
    Programmatic hooks (PreToolUse / PostToolUse) for guarantees. Prompts can stay for naturalness — but the hook is the safety net.
  4. 04High
    Sentiment-based escalation to human agents.
    Frustrated customers with simple problems just want their problem solved. Sentiment doesn’t track case complexity; you escalate easy wins and miss hard cases that arrive politely.
    Acknowledge the frustration verbally; escalate only on policy gaps, capability limits, explicit human request, or business thresholds.
  5. 05High
    Self-reported confidence scores for decision-making.
    The model has no inherent calibration. Its 0.9 might be 60% correct in practice — and confident hallucinations score high while correct hedged answers score low.
    Use explicit categorical criteria (human request, policy gap, no progress) backed by observable facts, not continuous self-rated confidence.
Domain 02 Tool Design & MCP Integration 4 patterns · 18% weight
  1. 06Critical
    Generic error messages (“Operation failed”).
    Strips signal the agent needs for recovery. The agent retries permission errors (waste), gives up on transient ones (lost requests), and can’t distinguish between “down” and “no match”.
    Return structured errors: isError, errorCategory, isRetryable, and human-readable context. Match recovery strategy to category.
  2. 07Critical
    Silently returning empty results for access failures.
    Agents cannot distinguish “no data found” from “couldn’t access the data”. Reports get written claiming “no findings” when the truth is the search never ran.
    Empty result → isError: false, results: []. Reserve the error flag for actual failures, with the failure type tagged.
  3. 08High
    Giving one agent 18+ tools.
    Tool-selection accuracy degrades rapidly above ~5 tools; similar tools create ambiguity and the synthesis agent starts doing research instead of synthesizing.
    Restrict each agent to 4–5 role-specific tools. Distribute the rest across specialized subagents; add scoped cross-role tools only for documented high-frequency needs.
  4. 09Critical
    Hardcoding API keys in .mcp.json.
    Configuration files committed to git ship your tokens to anyone with repo access. Rotation requires updating every developer’s checkout. A leaked repo is a leaked credential.
    Use ${ENV_VAR} expansion in the env block. Each developer sets the variable locally; secrets never enter version control.
Domain 03 Claude Code Configuration & Workflows 3 patterns · 20% weight
  1. 10Medium
    Putting team rules in ~/.claude/CLAUDE.md.
    User-level configs live on one laptop. They never reach teammates via git. The senior engineer’s “team standards” only apply to the senior engineer’s machine.
    Project-level .claude/CLAUDE.md for team standards (committed). Reserve ~/.claude/CLAUDE.md for personal preferences.
  2. 11High
    Using commands for verbose tasks that pollute context.
    Commands run in the current session, so their exploration noise lands in your main conversation. Telling a skill “be concise” doesn’t change where its outputs accumulate.
    Skills with context: fork + allowed-tools restrictions. Output stays in the subagent; you get back the summary.
  3. 12Critical
    Same-session self-review in CI/CD pipelines.
    Reviewers retain the generator’s reasoning context. You get confirmation bias rather than a fresh, independent assessment — the worst possible reviewer is the author.
    Separate sessions for code generation and code review. Treat the reviewer as a different person with no prior context.
Domain 04 Prompt Engineering & Structured Output 3 patterns · 20% weight
  1. 13Critical
    Vague instructions like “be thorough” or “find all issues”.
    Vague language is not a real lever. The model improvises a threshold per call. False positives, alert fatigue, and developer trust erosion follow — and lowering temperature doesn’t help because temperature controls sampling, not what counts as a finding.
    Rewrite criteria as inclusion + exclusion lists with explicit measurable thresholds (“flag functions exceeding 50 lines”). Anchor severity to concrete code examples.
  2. 14High
    Assuming tool_use guarantees semantic correctness.
    tool_use guarantees schema-compliant output, not semantic correctness. Numbers can still be wrong, fields swapped, line items hallucinated — the JSON parses fine.
    Add Pydantic semantic validators with cross-field checks. calculated_total vs stated_total is the canonical pattern.
  3. 15High
    Generic retry messages: “There were errors, please try again”.
    Without specifics, the model retries the same way. It has no signal for what requires correction; you burn API calls without convergence.
    Bound retries (2–3) and include the original document, the failed extraction, and the specific validation error in the retry prompt. Route persistent failures to human review.
Domain 05 Context Management & Reliability 3 patterns · 15% weight
  1. 16Critical
    Progressive summarization of critical customer details.
    Each summarization round loses specifics: names, IDs, amounts, dates, customer-stated expectations get condensed into “the customer wants a refund”. Bigger context windows don’t fix this — lost-in-the-middle still bites.
    Two-layer state: an immutable case facts block at context start (durable, structured) plus a summarized history layer (tone, intent). Numbers live in the facts block.
  2. 17Critical
    Aggregate accuracy metrics only (e.g., “95% overall”).
    Aggregate metrics mask per-category failures. Receipts at 99% can hide invoices at 70%. The headline number looks healthy while a downstream system is silently broken.
    Stratified metrics — track accuracy per document type / category / source. Surface the worst category, not just the average.
  3. 18High
    No provenance tracking for multi-agent data.
    Conflicting data from subagents cannot be resolved without knowing sources. The synthesis agent picks one value at random or averages incomparable numbers, producing a confident but wrong answer.
    Track source, confidence level, timestamp, and agent ID for every datum. Conflict resolution becomes a structured decision instead of a coin-flip.
