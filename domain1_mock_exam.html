Question01
Customer SupportLoop control

Your agentic loop terminates the conversation as soon as Claude returns any text content in its response. Production logs show that in 8% of cases, the agent stops mid-task — Claude returned a brief acknowledgment ("Let me check that for you") alongside a tool_use block, and your code interpreted the text as completion. What's the correct fix?

  • A Add a regex to detect closing phrases like "let me know" before terminating
  • B Inspect stop_reason explicitly: continue when it's "tool_use", terminate when it's "end_turn"
  • C Set a higher minimum text length threshold before treating a response as final
  • D Have Claude return only tool calls or only text, never both, by adjusting the system prompt
Correct: B

stop_reason is the structured signal the API guarantees. Text content is generated output that can accompany a tool call in the same response.

A: Regex is fragile and probabilistic. C: Length thresholds don't address the root cause. D: Constrains Claude unnaturally; doesn't fix the underlying control flow bug.
Question02
Multi-Agent ResearchContext passing

Your coordinator delegates to a web search subagent and a synthesis subagent sequentially. The synthesis subagent's output frequently contains the phrase "based on available sources" but never cites specific URLs, even though the web search subagent successfully returned 12 articles with full URLs. What's the most likely cause?

  • A The synthesis subagent's context window is too small to hold the URLs
  • B The web search subagent isn't returning URLs in a format the synthesis subagent recognizes
  • C The coordinator is passing the article content but not the URL metadata to the synthesis subagent's prompt
  • D The synthesis subagent needs its own web_fetch tool to retrieve the URLs
Correct: C

Subagents have no shared memory. If the coordinator passes article content without URLs, the synthesis agent can't cite them — they don't exist in its context. Fix: pass content separated from metadata.

A: Capacity isn't the issue if nothing was passed. B: Subagents don't communicate directly. D: Defeats specialization; URLs are already known to the coordinator.
Question03
Customer SupportCompliance gate

Your agent processes refunds. A new compliance requirement states: all refunds over $250 must trigger a notification to the compliance team via the notify_compliance tool before process_refund is called. You've added this rule to the system prompt, but logs show 4% of refunds over $250 skip the notification. What's the right architectural fix?

  • A Strengthen the prompt with bold formatting and few-shot examples showing correct sequencing
  • B Add a pre-tool-use hook that intercepts process_refund, checks the amount, and blocks the call if notify_compliance hasn't run for refunds over $250
  • C Add a PostToolUse hook on process_refund that retroactively calls notify_compliance after refunds complete
  • D Train the agent on a fine-tuned dataset of correct refund sequences
Correct: B

Compliance rules require deterministic enforcement. A pre-tool-use hook gates the sensitive operation before it executes — zero failure rate by construction.

A: Prompts remain probabilistic regardless of formatting. C: PostToolUse runs after the refund — too late for "before" requirements. D: Out of scope and over-engineered.
Question04
Multi-Agent ResearchLatency

Your coordinator runs three independent subagents — web search, internal docs, statistics database — sequentially. Total latency is 75 seconds and your SLA target is 30 seconds. None of the subagents depends on another's output. How should you reduce latency?

  • A Increase the coordinator's max_tokens to allow it to process subagents faster
  • B Switch to a faster model variant for all three subagents
  • C Have the coordinator emit all three Task tool calls in a single response so they execute in parallel
  • D Combine the three subagents into a single subagent with all three tools available
Correct: C

Parallel spawning happens within a single coordinator response. Three independent subagents become concurrent, total latency drops to the slowest one's runtime.

A: max_tokens doesn't affect tool execution. B: Optimizes individual subagent speed but keeps sequential structure. D: Re-introduces attention dilution and tool selection complexity.
Question05
Code GenerationSession state

You've been investigating a complex bug for two hours. The agent has read 30+ files and traced data flow through several modules. Overnight, a teammate merged a PR that renamed two of the modules involved and refactored their interfaces. You want to continue the investigation today. What's the right approach?

  • A Resume the session with --resume and let the agent re-read files when it needs them
  • B Use fork_session to create an independent branch from yesterday's analysis
  • C Start a fresh session and inject a structured summary of yesterday's findings (suspected functions, ruled-out hypotheses)
  • D Resume the session but increase the model's temperature to encourage re-analysis
Correct: C

Stale tool results in conversation history are dangerous — the agent reasons over outdated data without any signal it's wrong. Carry forward conclusions, not raw tool results.

A: Resuming preserves stale results. The agent has no mechanism to detect which are now wrong. B: Fork is for divergent exploration, not stale-context recovery. D: Temperature doesn't solve stale grounding.
Question06
Multi-Agent ResearchCoverage gaps

Your final research reports about "the impact of remote work on urban economies" consistently miss findings about transportation infrastructure and commercial real estate, even though the synthesis and web search subagents both execute cleanly per their logs. The coordinator's logs show it decomposed the topic into "remote work productivity," "remote work and employee wellbeing," and "remote work tools." Where do you investigate first?

  • A The synthesis subagent — it's failing to identify coverage gaps
  • B The web search subagent — its queries are too narrow
  • C The coordinator's task decomposition — it's mapped the topic onto worker-experience subtopics and omitted economic dimensions
  • D The document analysis subagent — it's filtering out economic sources
Correct: C

Output gaps trace back to coordinator decomposition. The logs show the coordinator mapped "urban economies" onto worker-experience subtopics — subagents executed correctly within their assigned (narrow) scope.

A, B, D: All blame downstream agents that worked correctly within their scope. The bug is upstream, in what they were assigned.
Question07
Customer SupportData normalization

Your agent integrates three MCP tools that return order timestamps in different formats: lookup_order returns Unix epochs, get_shipment returns ISO 8601 strings, and check_warehouse returns numeric date codes (YYYYMMDD as integer). The agent occasionally produces incorrect conclusions when comparing event ordering. What's the most reliable fix?

  • A Add detailed prompt instructions explaining each timestamp format and how to convert between them
  • B Implement a PostToolUse hook that normalizes all timestamps to ISO 8601 before they reach the agent
  • C Implement a pre-tool-use hook that rejects calls to tools with inconsistent timestamp formats
  • D Have the agent call a separate convert_timestamp tool before reasoning about dates
Correct: B

PostToolUse normalizes results before the agent sees them — deterministic and transparent. The agent reasons over consistent data without knowing the inconsistency existed.

A: Probabilistic fix to a deterministic problem. C: Wrong direction — pre-hooks intercept calls, not results. D: Adds tool-call overhead for every comparison; agent may forget to call it.
Question08
Code GenerationAttention dilution

You're reviewing a pull request that modifies 18 files across three modules. Your single-pass review produces inconsistent results: some files get detailed feedback, others get superficial comments, and the same code pattern is flagged as a bug in one file and approved in another. The team proposes upgrading to a model with a 1M token context window. Will this fix the problem?

  • A Yes — a larger context window allows the model to hold all files with room to spare, eliminating the inconsistency
  • B Yes — but only if combined with a higher reasoning budget setting
  • C No — attention dilution is independent of context window capacity; the fix is splitting into per-file passes plus a separate integration pass
  • D No — the model needs more training data on multi-file reviews
Correct: C

Attention dilution is a cognitive load issue, independent of capacity. Decomposition into focused passes is the fix.

A, B: Both confuse capacity with focus. D: Out of scope and doesn't address the architectural issue.
Question09
Multi-Agent ResearchError propagation

Your coordinator spawns a web search subagent that times out after 60 seconds while researching a niche topic. You need the coordinator to make an intelligent recovery decision (retry with a modified query, try an alternative subagent, or proceed with partial results). Which error propagation approach best supports this?

  • A The subagent catches the timeout and returns an empty result set marked as successful
  • B The subagent returns structured error context including the failure type, attempted query, partial results obtained before timeout, and potential alternative approaches
  • C The subagent propagates the timeout exception directly to a top-level handler that terminates the workflow
  • D The subagent retries internally with exponential backoff and returns a generic "search unavailable" status only after all retries fail
Correct: B

Structured error context lets the coordinator make intelligent recovery decisions: retry with a modified query, try an alternative, or proceed with partial results.

A: Suppresses the error — silent failure. C: Terminates the entire workflow unnecessarily. D: Generic status hides valuable context from the coordinator.
Question10
Customer SupportHuman handoff

Your AI agent decides to escalate a complex billing dispute to a human agent. When the human picks up the ticket, the customer is frustrated because the human asks them to re-explain everything they already told the AI. What's the root cause and the correct fix?

  • A The AI should have resolved the issue itself instead of escalating; add stricter escalation criteria
  • B The human agent has no access to the conversation transcript; the AI must compile a structured handoff summary including customer ID, conversation summary, investigation results, root cause, and recommended action
  • C The customer should be informed before escalation that they'll need to re-explain the issue
  • D The AI should automatically forward the raw conversation transcript to the human via email before escalation
Correct: B

The human reviewer has no transcript access by default. The AI must compile a structured handoff with all required fields so the human starts informed.

A: Solves a different problem; the issue is about handoff quality, not escalation criteria. C: Worsens UX by accepting the broken pattern. D: Raw transcripts aren't structured for fast human consumption.
