2.1 Tool interface design 2 q
Q01 Task 2.1Description components

Two tools, analyze_content and analyze_document, both with the description "Analyzes the input." What's the highest-leverage fix, and why?

Model answer

Rename one to reflect a distinct contract (e.g., extract_web_results for the web-flavored tool) AND rewrite both descriptions with purpose, input format, examples, edge cases, and boundary statements. The rename helps differentiate at the name level, but the descriptions are what Claude actually reads to select. Both changes together; description rewrite is the heavier lift.

Q02 Task 2.1System prompt trap

True or false: if descriptions are perfect, the system prompt cannot cause misrouting. Explain.

Model answer

False. Keyword-heavy system prompts pull Claude toward similarly-named tools regardless of description quality. A prompt phrase like "always begin by analyzing the content" creates an association that overrides clean descriptions. Audit the prompt for verbs and nouns that match tool names; replace keyword-loaded phrasing with goal-based instructions.

2.2 Structured error responses 2 q
Q03 Task 2.2Lost signal

A web search subagent times out. The coordinator gets back a generic "search unavailable" status. What information has been lost that the coordinator needs to make an intelligent recovery decision?

Model answer

The error category (transient vs business vs permission), retryability, what was attempted (which query, which sources), partial results already gathered, and alternative approaches the coordinator might try. Without these, the coordinator can only choose between blind retry and giving up — neither of which leverages the recovery options that were available.

Q04 Task 2.2Business error

Your process_refund tool gets a request for $750 when policy caps refunds at $500. What errorCategory should it return, and what isRetryable value? Why?

Model answer

errorCategory: "business", isRetryable: false. This is a policy violation, not a transient failure — retrying with the same amount will fail again. The agent needs to either explain to the user (with a customer-friendly message and the policy limit in details) or escalate to a human approver. Marking it retryable wastes calls and obscures the actual situation.

2.3 Tool distribution & tool_choice 2 q
Q05 Task 2.3Over-provisioning

A synthesis agent has 18 tools available — search, fetch, document analysis, citation formatting, summarization, verification, and more. It produces inconsistent output and frequently uses tools outside its synthesis role. Is the answer "better prompts" or something structural?

Model answer

Structural. Restrict the synthesis agent's toolset to 3-5 tools that match its role: compose_section, format_citations, plus a scoped verify_fact for high-frequency cross-role needs. Selection reliability degrades with tool count; better prompts can't fix a structural over-provisioning problem. The synthesis agent will keep using web search whenever it has access to web search.

Q06 Task 2.3tool_choice

You have three extraction tools (invoice, receipt, contract) and the document type is unknown. You want to guarantee Claude calls one of them and doesn't return conversational text. What tool_choice value?

Model answer

tool_choice: {"type": "any"}. This forces a tool call but lets Claude pick which extractor based on the document. "auto" would let Claude return conversational text; forced selection on a specific tool would lock you to one extractor regardless of document type. "any" is the right balance — guaranteed structured output, model-driven selection.

2.4 MCP server integration 2 q
Q07 Task 2.4Scope diagnosis

A new team member clones the repo and runs Claude Code. They report none of the MCP tools you set up are available. You configured them in ~/.claude.json on your machine. What's the fix?

Model answer

Move the server configurations from user-level ~/.claude.json into project-level .mcp.json committed to the repo. Use ${ENV_VAR} expansion for credentials so secrets stay out of git. The new team member then gets all servers automatically on clone, with each developer providing their own tokens via shell environment.

Q08 Task 2.4Resources vs tools

You want to give the agent visibility into your full Jira issue catalog without making it call list_issues first. Tools or resources? Why?

Model answer

Resources. Expose the issue catalog as an MCP resource. The agent sees the full inventory at connection time without exploratory tool calls. Pattern: tools for actions (creating, updating, transitioning), resources for content catalogs (issue summaries, schema, doc hierarchies). Using list_issues as a tool wastes a round trip every session.

2.5 Built-in tools 2 q
Q09 Task 2.5Grep vs Glob

You need to find every file that imports the lodash library. Grep or Glob? Why does the other one fail?

Model answer

Grep, searching for from 'lodash' or require('lodash') across file contents. Glob fails because it only matches paths — **/*lodash* would only catch files NAMED with "lodash" in their path, missing every file that imports the library by name. Mental rule: contents = Grep, paths = Glob.

Q10 Task 2.5Edit fallback

Edit fails on a config file because the string "port: 3000" appears in five places. What's the correct fix? Why isn't the answer "add more context lines until the snippet becomes unique"?

Model answer

Read the full file → construct the modified content → Write it back. Adding more context lines works for a while but breaks on genuinely repetitive files where any reasonable snippet is non-unique. You're fighting the tool. Read+Write is reliable across any file shape; it's the documented fallback for non-unique-match failures.
