The brief

Configure the payments-service.

You are the architect on a TypeScript payments service. The team has just adopted Claude Code. Your job is to configure the repository so every developer — and the CI pipeline — works against the same standards. Use what you learned across Tasks 3.1 through 3.6.
Exercise · the repository to configure
Tasks 3.1 → 3.6

Set up payments-service so the team's coding standards, file-type conventions, audit workflows, and PR review pipeline are all configured correctly. Wrong-by-one-directory costs you the question.

Required artifacts

  1. A project-level CLAUDE.md at the repo root that holds universal team standards (TypeScript strict, conventional commits, never log card data, money in cents) and severity definitions for review. It should compose smaller rule files via @import rather than become a monolith.
  2. Three path-scoped rule files under .claude/rules/: one for tests (Vitest, fixtures), one for API handlers (Zod, ApiError, idempotency), one for migrations (up/down, no data backfill in schema migrations). Each loads only when matching files are being edited.
  3. A skill at .claude/skills/audit-deps/SKILL.md that scans package.json files for outdated and vulnerable dependencies. The verbose audit output must not pollute the main session — only the summary returns.
  4. A GitHub Actions workflow that runs Claude as a PR reviewer using the non-interactive flag, emits machine-parseable JSON output, deduplicates findings against prior runs via a cache, and posts inline comments to the PR.

Constraints

  • Tests are co-located with source (handler.ts next to handler.test.ts) — they are spread across many directories.
  • The audit-deps skill must use only Read, Glob, and Bash tools; it should prompt the user for which directories to scan.
  • The CI reviewer must skip Prettier-handled style nits and report only new or still-unaddressed issues across commits.
  • Nothing that should be shared with teammates may live under ~/.claude/.

01
Project-level CLAUDE.md (universal standards + imports)
Task 3.1

Universal team standards live at the top. Topic-specific rules are @import-ed from .claude/rules/ so the file stays small and reviewable. Severity definitions belong here because both interactive Claude Code sessions and the CI reviewer load this file.

CLAUDE.md markdown 
# Payments Service

## Universal standards
- TypeScript strict mode. No `any` without a comment justifying it.
- Conventional commits (feat:, fix:, chore:, docs:).
- Never log raw card data, full PANs, CVVs, or PII. Use the redactor.
- All money in cents (integer). Never store as float.

## Severity definitions for review
- Critical: vulnerability, data leak, regulatory violation, broken core flow
- High: correctness bug, security hardening miss, broken tests
- Medium: maintainability, missing test coverage on new logic
- Low: nits — skip these in CI review (Prettier handles style)

# topic-specific rules load only when matching files are edited
@import .claude/rules/testing.md
@import .claude/rules/api-handlers.md
@import .claude/rules/migrations.md
02
Three path-scoped rules under .claude/rules/
Task 3.3

Each file declares a paths glob in YAML frontmatter. Tests are scattered across the codebase, so **/*.test.* catches them all from one file — directory-level CLAUDE.md would force duplication. API handlers live under one subtree but using a path glob keeps the pattern uniform with the others. None of these load while editing unrelated code, so token usage stays lean.

.claude/rules/testing.md markdown 
---
paths: ["**/*.test.ts", "**/*.spec.ts"]
---
- Vitest. describe/it. No snapshots.
- Reuse fixtures in tests/fixtures/ before creating new ones.
- Mock external HTTP at the boundary (msw), not at the function level.
- One failure mode per test. Don't conflate cases.
.claude/rules/api-handlers.md markdown 
---
paths: ["src/api/**/*.ts"]
---
- Async/await. Wrap business logic in try/catch.
- Validate input with Zod at the entry point.
- Return ApiError on failure: { code, message, statusCode }. Never throw raw.
- Idempotency keys required on POST /charges and POST /refunds.
- Never log card data — use redactor utility.
.claude/rules/migrations.md markdown 
---
paths: ["src/db/migrations/**/*.ts"]
---
- Every migration has up() and down() — both tested.
- No data backfill in schema migrations. Use a separate backfill script.
- Add new columns nullable first, backfill, then NOT NULL in a follow-up.
03
audit-deps skill with context: fork
Task 3.2

The whole point of this skill is verbose discovery — reading every package.json and parsing audit output. Without context: fork, that flood lands in the main session. With it, the subagent does the work and only the consolidated summary returns. allowed-tools caps the blast radius — no Edit, no Write. argument-hint documents what the user must supply.

.claude/skills/audit-deps/SKILL.md markdown 
---
name: audit-deps
description: Scan package.json files for outdated deps and vulnerabilities; return a consolidated summary.
context: fork
allowed-tools: [Read, Glob, Bash]
argument-hint: "Glob for directories to scan, e.g. 'packages/**' or '.'"
---

You are auditing dependencies. Steps:

1. Glob for all package.json files matching the provided glob.
2. In each directory, run `npm audit --json` and parse the result.
3. Aggregate: outdated count, severity breakdown, and the top 10
   critical vulns with package, version, CVE, and recommended fix.
4. Return ONLY the aggregated summary. No per-package output.
   No raw JSON.

Output format:
- Outdated total: <n>
- Severity: critical=<n>, high=<n>, moderate=<n>, low=<n>
- Top critical:
  - <pkg>@<ver>  CVE-XXXX-XXXX  fix: upgrade to <ver>
04
JSON schema for review output
Task 3.6

The schema enforces structured output the CI script can post as inline PR comments. Each finding carries the file, line, severity, category, message, and an optional suggestion. Without the schema, parsing variable text is brittle.

.ci/review-schema.json json 
{
  "type": "object",
  "required": ["findings"],
  "properties": {
    "findings": {
      "type": "array",
      "items": {
        "type": "object",
        "required": ["file", "line", "severity", "category", "message"],
        "properties": {
          "file":       { "type": "string" },
          "line":       { "type": "integer" },
          "severity":   { "enum": ["critical", "high", "medium", "low"] },
          "category":   { "enum": ["security", "correctness", "perf", "tests", "maintainability"] },
          "message":    { "type": "string" },
          "suggestion": { "type": "string" }
        }
      }
    }
  }
}
05
CI workflow with -p, JSON output, and prior-findings cache
Task 3.6

The four levers all show up here: -p stops the job from hanging waiting for stdin; --output-format json + --json-schema give parseable output; the cache + the explicit "report only new or still-unaddressed" instruction prevents duplicate review comments across commits; and the workflow runs in a fresh session every time, so it's an independent reviewer rather than the generator reviewing its own work.

.github/workflows/claude-review.yml yaml 
name: Claude PR Review
on:
  pull_request:
    types: [opened, synchronize]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }

      - name: Restore prior findings
        uses: actions/cache@v4
        with:
          path: .ci/prior-findings.json
          key: claude-findings-${{ github.event.pull_request.number }}

      - name: Run Claude review
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          PRIOR=$(cat .ci/prior-findings.json 2>/dev/null || echo "[]")
          DIFF=$(git diff origin/${{ github.base_ref }}...HEAD \
                 -- ':!**/*.lock' ':!**/dist/**')

          claude -p "$(cat <<EOF
          Review this diff per CLAUDE.md severity rules.
          Skip 'low' severity (style) — Prettier handles those.

          Prior findings already reported on this PR:
          $PRIOR

          Report ONLY new or still-unaddressed issues.
          Output must conform to the provided schema.

          --- DIFF ---
          $DIFF
          EOF
          )" \
            --output-format json \
            --json-schema .ci/review-schema.json \
            > review.json

      - name: Post inline PR comments
        run: ./scripts/post-pr-comments.sh review.json

      - name: Persist findings for next run
        run: cp review.json .ci/prior-findings.json
