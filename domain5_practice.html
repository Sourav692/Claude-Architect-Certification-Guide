5.1 Context preservation 1 q
Q01 Task 5.1Forgotten facts

A returns agent's first-contact resolution drops sharply after turn 12. Logs show the summarized history reads "customer wants refund for defective item" — but the original message specified $249.99, order #77302, Feb 8. The agent now repeatedly asks the customer to re-state these. What's the underlying cause and the right fix?

Model answer

Progressive summarization compressed transactional facts into vague language. The fix is a persistent case facts block: extract order_id, refund_amount, purchase_date, issue_type into a structured durable layer that's re-injected into every prompt outside the summarized history. Numbers can't drift if they live outside the lossy layer.

Wrong instinct: "increase context window" — capacity isn't the issue, the facts are getting summarized away. "Disable summarization" — loses tone/intent coherence, blows tokens. The fix is layering, not capacity.
5.2 Escalation & ambiguity 1 q
Q02 Task 5.2Multiple matches

Your agent calls get_customer(name="John Smith") and the tool returns three records. The agent picks the one with the most recent order and proceeds with a refund. Two days later, the wrong customer's account got refunded. What pattern should the agent have followed?

Model answer

When tool results return multiple matches, the agent must ask the customer for an additional identifier — email, phone, order number — rather than selecting based on heuristics. Heuristic selection on identity is dangerous: the wrong account gets the action, and the customer never sees the ambiguity. Add explicit instructions in the system prompt: "When multiple matches are returned, request clarification."

5.3 Error propagation 1 q
Q03 Task 5.3Silent failure

A research coordinator delegates to a web_search subagent. The subagent's API call times out after 30s. Current behavior: catch exception, log it, return {"results": []}. The coordinator then synthesizes a report stating "no relevant sources were found." What's the most accurate critique?

Model answer

Silent suppression conflates access failure with a valid empty result. The coordinator can't tell "search broke" from "search ran but found nothing" — and the report misleads users by stating no sources exist when in reality the source was unreachable. Fix: subagent returns structured error context (error_type, is_retryable, attempted_query, partial_results, alternatives) so the coordinator can decide retry, alternative source, or annotate the gap in the report.

5.4 Codebase exploration 1 q
Q04 Task 5.4Context degradation

A 4-hour codebase exploration session starts producing answers like "this codebase typically uses a service layer" and "the RefundService class probably calls..." — even though earlier in the session, Claude examined those exact classes specifically. What's happening?

Model answer

Context degradation. The model has read so much verbose discovery output that earlier specific findings are buried — it's pattern-matching to generic software knowledge instead of citing the actual classes it examined. Fix: spawn subagents for verbose discovery (return summaries only), persist key findings to scratchpad files, inject summaries when starting new investigation phases, and use /compact when the running context fills up.

Wrong instinct: "increase context window" — degradation is about attention quality, not capacity. "Restart from scratch" — discards hours of valuable work.
5.5 Human review & confidence 1 q
Q05 Task 5.5Aggregate trap

An extraction pipeline reports 97% aggregate accuracy on a labeled validation set. Leadership wants to reduce human review by 80%. What's the right preflight check before doing this?

Model answer

Break down accuracy per document type AND per field — verify no segment has materially lower accuracy. Aggregate metrics can mask 70% accuracy on a critical field within a specific document type (e.g., tax fields on EU invoices). Only after segment-level validation, plus stratified sampling thresholds in production, is it safe to reduce review.

5.6 Information provenance 1 q
Q06 Task 5.6Trend or conflict

A multi-agent research system synthesizes findings from three sources on EV battery prices. Source A (Mar 2024) reports $139/kWh. Source B (Dec 2024) reports $115/kWh. Source C (Sep 2025) reports $108/kWh. The synthesis subagent currently outputs: "EV battery prices are around $120/kWh." Critique this output.

Model answer

The output loses source attribution and temporal context. Synthesis should preserve all three values with source names and publication dates, and present them as a declining trend — not a single averaged number. Conflict-resolution rules apply only when sources are contemporaneous; different dates plus different numbers means the metric moved over time, not that sources disagree.

Wrong instinct: "average them" fabricates a number no source reported. "Pick the most recent" discards trajectory information stakeholders need.
