01 — Orientation

How the exam works.

The Foundations exam validates that practitioners can reason about real-world tradeoffs when shipping production systems on Claude. Questions are grounded in actual customer engagements — agentic support systems, multi-agent research pipelines, CI/CD code review, structured extraction. You will be tested less on memorisation and more on architectural judgment.

The Core Surface Four technologies underpin every question on the exam: Claude Code (the configured CLI), the Claude Agent SDK (loop control, hooks, subagents), the Claude API (tool use, structured output), and the Model Context Protocol (MCP) (tool and resource interfaces).

What the test rewards

  • Practical judgment about when to use deterministic enforcement (hooks, gates) versus prompt-based guidance.
  • Architectural choices: when to fork sessions, when to spawn subagents, when to use plan mode.
  • Clean tool design — naming, descriptions, scoping, structured errors — over clever prompting.
  • Reliability instincts: escalation paths, self-evaluation patterns, error categorisation.
Logistics at a glance

All questions are multiple choice with one correct answer and three distractors. Unanswered questions are scored as incorrect — there is no penalty for guessing. Four of six possible scenarios are drawn at random, so you should feel comfortable across all six. The scaled passing score is 720 of 1000.

Checkpoint
  • Can you name the four core technologies the exam covers?
  • Do you know which domain carries the heaviest weight?
  • Could you sketch one production scenario end-to-end before reading the chapters?

04 — Method

A preparation playbook.

The ideal candidate has six months or more of hands-on production work with Claude — APIs, Agent SDK, Claude Code, MCP. If that's you, treat the chapters as revision. If not, treat them as a syllabus and pair each module with a small build of your own.

What experienced architects already know

  • How to inspect stop_reason to drive an agentic loop without arbitrary iteration caps.
  • Why coordinator agents must explicitly pass context to subagents — they don't inherit it.
  • When deterministic hooks beat well-written prompts: any time a guarantee is required.
  • How tool descriptions determine routing far more than system-prompt instructions.
  • The difference between resuming a session and starting fresh with a structured summary.

A reading rhythm that works

Three-pass discipline

Pass 1 — Survey. Read each module hero and section labels only. Build a map of the territory. Pass 2 — Depth. Read sequentially, pausing at every checkpoint. Sketch the agent graph or tool surface in your own notebook. Pass 3 — Recall. Close the module. From memory, re-derive the key idea, the anti-pattern, and the production tradeoff for each task statement.

The weight heuristic Domain 1 alone is 27% of the exam — more than any single other domain. If you have limited preparation time, give it disproportionate attention. Domains 3 and 4 each carry 20%. Domain 2 (18%) and Domain 5 (15%) reward depth over breadth.

What the modules contain

  • Knowledge of — the conceptual claims you should be able to state cold.
  • Skills in — the production decisions you should be able to make under pressure.
  • Anti-patterns — the specific failure modes the exam tests against.
  • Worked examples — code, prompts, and architectural sketches grounded in real scenarios.
